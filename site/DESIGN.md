# The Foton website — design

Why the site is built the way it is. Accepted 2026-08-31. Written in English to
sit with `AGENTS.md` and `PARITY.md`; the site itself is in English for the same
reason.

## What this is for

Foton has no web presence. The README does the whole job today, which works for
someone already on GitHub and not at all for anyone else.

**Audience: server operators.** People who would host Foton. The one action the
site exists to produce is a first world running on their machine.

That choice has a cost the design has to pay for. The README tells people not to
put Foton in front of a community they care about, and an operator-facing site
is an invitation to do exactly that. So the honesty is not optional decoration
here — it is what makes the invitation defensible. There is no parity page in
scope, so the home page carries it instead: a pre-alpha band directly under the
hero, and a section that names what does not work yet rather than listing only
what does.

### In scope

- A home page.
- A getting-started guide.
- A generated configuration reference.
- A contributing guide.

### Out of scope

- A parity page. The home page carries a condensed status section instead.
- Any visual integration of the rustdoc output. It is parked at a sub-path and
  keeps its own default theme.
- A blog, a changelog, search, analytics, comments, i18n, dark mode.

## Three decisions

### 1. The site is generated by a script in `dev/`, not by a site generator

`dev/` already generates the logo, the configuration reference and the parity
ledger. `dev/gen-site.py` belongs to that family, and it adds no toolchain: the
repository has no Node and no JavaScript, and CI has neither. Astro would author
content more comfortably but drags in npm and a lockfile. Zola is a single Rust
binary and would theme well, but the configuration page still needs the Python
that reads the schemas, so Zola would be a second tool rather than the only one.

The site is small — four pages — and art-directed, which is where hand-rolling
costs least and a general-purpose theme fights hardest.

### 2. Prose is written by hand. Facts are generated. Never the other way round

This is the repository's own rule applied to the site. Generated from source at
build time:

| Fact | Source |
|---|---|
| version, Minecraft target | `version = "0.15.2+mc26.2"` in `Cargo.toml` |
| protocol number | `version` in `foton-registry/build_assets/packets.json`, the extracted data |
| block / item / entity coverage | `dev/coverage.py` |
| the named missing classes | `dev/parity-gaps.txt` |
| in-world script count | a glob of `dev/*-test.sh` |
| unit test count | `dev/test-counts.json` (see below) |
| every configuration key, type, default and range | `package-content/*.schema.json` |

The unit test count is the one fact that cannot be read cheaply: getting it
means compiling the workspace. `dev/ci.sh` already runs `cargo test --workspace`,
so it writes the count to `dev/test-counts.json` on the way past, and a
`--check` run fails when the committed value has drifted. That is the pattern
`dev/parity-gaps.txt` already uses: generated where the information exists,
committed so everything else can read it for free, guarded so it cannot rot.

Prose lives in HTML fragments under `site/content/`, with named holes the
generator fills. No fact a reader could check is ever typed into a fragment.

Consequence: no Markdown dependency. The site does not render the repository's
`.md` files — they are written for GitHub, and re-rendering them would produce a
worse page than writing one. The prose is authored for the web; only the facts
are shared.

`dev/ci.sh` gains a `--check` run of the generator, beside the one that already
guards `CONFIGURATION.md`. What it can guard is different, though: the site's
output is not committed, so there is nothing to diff. See *Verification*.

### 3. The site takes the `gh-pages` root; rustdoc moves to `/api/`

Two workflows force-pushing `single-commit` to the same branch erase each other,
so one deployment has to produce both. `docs.yml` gains a step that builds the
site into the deploy root and copies `target/doc` into `api/`.

This is not integration: no shared navigation, no shared theme, no link from the
site's chrome. The rustdoc is parked so it stops colliding.

If a real domain is wanted later, the alternative is a separate host
(Cloudflare Pages, Vercel) with `gh-pages` left to rustdoc alone. That is a
deployment change, not a design change.

## Visual direction

Direction E, *Isometric Atlas*, from the design canvas:

- Warm paper ground `#f0ece2`, ink `#17150f`, accent `#b0741a`.
- Bricolage Grotesque for display, DM Mono for data and code.
- Voxel scenes rendered by `dev/gen-logo.py`'s own scanline renderer,
  generalised from its single wall plane to an `(i, j, k)` space. Cube edge 12
  source pixels at scale 5 — the mark's own settings, so every pixel on the site
  is the same size as the pixels in the logo.
- Materials keep the three-shades-per-face trick: grass, stone, deep stone and
  glow.

## Site map

| Path | Job |
|---|---|
| `/` | Make the case, and say plainly where the project stands |
| `/start/` | A world running in under ten minutes, by any of three routes |
| `/configuration/` | Answer "what does this key do, what is its default" |
| `/contributing/` | Take someone from curious to a first change |
| `/api/` | Parked rustdoc, unthemed |

### Home

1. **Hero.** The headline, one sentence of what Foton is, the primary call to
   action, and a copyable run command. The isometric island.
2. **Pre-alpha band.** Immediately under the hero, not in the footer. You can
   connect, build, and come back to a saved world; survival gameplay is
   incomplete.
3. **What works today.** Concrete and operator-shaped: connecting, building,
   Anvil worlds that save and reload, containers and furnaces, hostile mobs and
   animals, redstone, world generation, RCON, permission groups, multiple
   worlds.
4. **What does not work yet.** The named gaps, generated. A site that opens its
   own defects is the only version of this page that is honest.
5. **Why it behaves like vanilla.** Three beats: written against the decompiled
   source, values come out of an extractor, observable behavior wins over a
   faster design.
6. **How it is checked.** The two layers and their counts, generated.
7. **The AGPL network clause.** For this audience this is not a legal footnote,
   it is a deployment constraint: serve this code to third parties and they are
   entitled to its source. The README already calls it the part that surprises
   people. It gets a real section, not a footer line.

### Get started

Requirements. Three install routes — release binary, the `scratch` Docker image,
from source with the pinned toolchain. What the first boot writes to disk
(`config/config.toml`, `config/worlds.toml`, `config/groups.toml`, `.logs/`).
Connecting a client. Where worlds are stored. RCON and the console. How to
report a bug, including that `/bug` opens a real form in-game.

### Configuration

The three files, every key with type, default, range and description, navigable
by section. Generated.

### Contributing

The bar a change clears. The engineering rules, condensed. The central
mechanism: name a struct exactly after its vanilla class, annotate it, and the
build finds it and writes the registration — there is no registry list to edit.
The checks: `dev/doctor.sh`, `dev/ci.sh`, `dev/all-tests.sh`.

## Structure

```
site/
├── content/          hand-written HTML fragments, one per page
├── static/           favicon, any fonts we self-host
└── dist/             build output, git-ignored
dev/
├── gen-site.py       the generator
├── config_schema.py  schema walking, extracted (see below)
└── voxel.py          the logo's renderer, generalised (see below)
```

Two extractions, both because a second consumer appears and neither script
should grow a fork of the other's logic:

- **`dev/config_schema.py`** — `resolve`, `ref_name`, `type_of`, `limits`,
  `default_of` move out of `gen-config-docs.py`, which keeps its Markdown
  rendering and imports them. `gen-site.py` imports the same functions and
  renders HTML. One description of the schema format, two outputs.
- **`dev/voxel.py`** — `Grid`, `cube` and the run-merging SVG emitter move out of
  `gen-logo.py`, generalised to `(i, j, k)`. `gen-logo.py` keeps `CELLS`,
  `largest_fitting_unit` and `center`, and calls into it for its single plane.

`dev/coverage.py` gains a `counts()` function returning the numbers its `main()`
currently prints, so the site reads data rather than parsing stdout.

## Verification

`site/dist/` is git-ignored and built in CI, so there is no committed output to
diff. What is worth checking is that the build cannot silently produce a broken
or dishonest page:

- `python3 dev/gen-site.py --check` builds into a temporary directory and fails
  on an unfilled hole or an internal link pointing at a file the build did not
  emit. A renamed fact breaks the build instead of shipping `{{ }}` to a reader.
  Wired into `dev/ci.sh` beside the existing config-docs check.
- `python3 dev/ci.sh`'s test-count step fails when `dev/test-counts.json` has
  drifted from what the suite actually reports.
- The existing `parity_ledger_matches_the_generated_gaps` test already guards
  the gap list the home page reads.

Deliberately not tested: prose, layout, and anything that would only restate a
constant.

## Risks

- **The site drifts from the project's real state.** Mitigated for every fact
  that is generated; unmitigated for prose. "What works today" is the section
  most likely to age badly, and it is the one an operator most relies on.
  Accepted, and it is why the numbers around it are generated.
- **Hand-rolling costs more than expected** once the fourth page wants
  navigation, anchors and code highlighting. The escape hatch is Zola, which
  would keep `config_schema.py` and replace only the templating.
- **Inviting operators onto a pre-alpha server.** Addressed by placement and
  wording, not solved. If the honesty sections get trimmed later, the site
  becomes dishonest.

## Follow-up, not in this work

The design canvas still carries six directions across two pages. Once the site
ships, it should be consolidated to the retained one.
