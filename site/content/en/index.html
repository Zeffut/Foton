A Minecraft server that refuses to guess.

Foton is an independent implementation of the Java Edition server, written in Rust. Every registry, block, item and worldgen value comes out of an extractor — nothing is written from memory, nothing is transcribed by hand.

THE THESIS

Parity is the specification, not the goal.

Anything a player can observe — gameplay, protocol, registries, world generation — is written against the decompiled vanilla source, which sits in the tree while the code is written. When a faster or more idiomatic Rust design would change observable behavior, the observable behavior wins.

Concurrency, but only where vanilla allows it. Gameplay ticks stay synchronous, because vanilla semantics depend on the order things happen in. Chunk generation, lighting, packet processing and chunk sending do not, and they run off the tick.

HOW IT IS BUILT

Nothing here is transcribed by hand.

A file maps every vanilla registry entry to the Java class behind it. At build time the generator scans for structs carrying a behavior attribute, matches the struct name against that map, and writes the registration itself.

So implementing a block means creating a struct named exactly after its vanilla class, in the right directory. There is no registry list to edit and no wiring to remember — and a behavior the generator cannot see is a behavior that does not exist, which is a mistake the build can catch and a human cannot.

#[block_behavior]
pub struct LanternBlock;   // the name is the registration
ARCHITECTURE

One direction of dependency.

The binary sits on the login layer, which sits on the game logic, which rests on leaves that know nothing about each other — worldgen, protocol, the generated registry, the macros, the spatial and math primitives, and the crypto.

Nothing below the game logic can reach back up into it. That is what keeps the registry generated rather than hand-maintained.

VERIFICATION

Two layers, because a unit test cannot see that a furnace has no behavior.

{{ unit_tests }}
TESTS THAT RUN IN PROCESS

They cover the places where being wrong is silent: component hashing, seeded RNG determinism, protocol encoding, loot table evaluation, permission resolution.

{{ inworld_scripts }}
IN-WORLD SCRIPTS

Each boots a real server on its own port and talks to it over the Minecraft protocol. They catch what compiles and still does not work — which is how three furnaces were found to have no behavior at all.

GET IT RUNNING

One command, then a world.

The world generates, saves to the Anvil format vanilla uses, and reloads where you left it. Containers, furnaces, redstone, hostile mobs and animals, villagers, RCON and permission groups all work today; survival gameplay is still landing.

cargo run -p foton
