Charges a list without materializing it.

NbtList::as_nbt_tags deep-clones every element it hands back, so measuring a list through it cloned the whole subtree once per nesting level: a two megabyte custom_data component of 511 nested lists ending in a byte array peaked near a gigabyte of live heap, and the packet was rejected afterwards anyway. Vanilla never has this problem because NbtAccounter charges each tag as it is parsed rather than measuring a finished tree.

Every charge below is the one vanilla_nbt_heap_size gives the same tag, so the quota itself is unchanged.
