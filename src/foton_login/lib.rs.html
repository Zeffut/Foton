9// The release profile sets `panic = "abort"`, so an `expect` a running server
10// can reach is not a style question: it kills the process without unwinding,
11// `shutdown_worlds()` never runs, and every dirty chunk goes with it. The lint
12// is scoped to `not(test)` on purpose -- a panicking test is how a test reports
13// a failure, while a panicking server is how a world is lost.
14#![cfg_attr(not(test), warn(clippy::expect_used))]
15#![cfg_attr(not(test), warn(clippy::panic, clippy::unreachable, clippy::todo))]
